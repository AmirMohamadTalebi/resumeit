# بررسی سپ و تنظیمات میزبان — ۲۱ اکتبر۲۰۲۶

خطای گزارش‌شده POST /api/payments/invoices/{id}/pay با503 پیش از بازشدن بانک است. علت محیط زنده هنوز تأیید نشده؛ مرورگر به‌تنهایی کد خطای واقعی سپ را نشان نمی‌داد.

## تنظیمات معتبر

```env
SEP_ENABLED=true
SEP_TERMINAL_ID=شماره ترمینال تاییدشده با ارقام انگلیسی
PUBLIC_ORIGIN=https://resumeit.ir
HOST=0.0.0.0
```

PORT پورت داخلیِ برنامه است و باید با پورت سرویس رانفلر برابر باشد؛ پیش‌فرض کد5077 است. اگر رانفلر PORT را اختصاص می‌دهد همان مقدار ملاک است. پورت داخلی را به PUBLIC_ORIGIN اضافه نکن. نام متغیر جداگانه‌ای برای callback یا پورت سپ وجود ندارد.

مسیر عمومی callback: `https://resumeit.ir/api/payments/sep/callback`؛ برای هر سفارش، key و id تصادفی به query اضافه می‌شود. آن‌ها را در گزارش یا تصویر منتشر نکن. HTTPS عمومی روی443 است؛ دریافت callback نیاز به همان شماره پورت داخلی در تنظیم بانک ندارد. تنظیمات پنل و تأیید IP خروجیِ واقعی باید از محیط میزبان/سپ بررسی شود؛ این جلسه دسترسی قابل‌استفاده به لاگ رانفلر نداشت.

دو شرط فعال‌بودن: تنظیم محیط SEP_ENABLED و ترمینال معتبر، و مجوز فعال سپ در سیاست پرداخت پنل مدیریت. فایل .env.example تنظیم محیط رانفلر را تغییر نمی‌دهد. پس از تغییر متغیرهای رانفلر، سرویس باید با متغیرهای جدید اجرا شود.

## اصلاح و شواهد

- نام فیلد درخواست توکن با نمونهٔ JSON مستند فنی۳٫۶ ارسالی کاربر، RedirectUrl، هم‌خوان شد. خود جدول مستند املای RedirectURL را هم دارد؛ بنابراین تغییر حروف به‌تنهایی علت قطعی503 محسوب نمی‌شود.
- URL توکن، verify و reverse با مستند فنی۳٫۶ تطبیق دارند. چند نمونهٔ قدیمی Postman/ASP.NET املای Transcation دارند، ولی PDF اصلی Transaction را مشخص کرده؛ endpointها تغییر نکردند.
- خواندن SEP_ENABLED در برابر فاصله و حروف بزرگ مقاوم شد؛ مقدار false همچنان خاموش می‌کند و ترمینال نامعتبر فعال نمی‌شود.
- دریافت توکن در خطا کد امن دارد: SEP_TOKEN_{errorCode} برای پاسخ رد بانک؛ GATEWAY_HTTP_{status}، GATEWAY_INVALID_RESPONSE، GATEWAY_TIMEOUT یا کد مجاز شبکه. خطای ناشناخته TOKEN_FAILED می‌ماند.
- لاگ ساخت‌یافته payment_token_failed فقط provider و کد مجاز را ثبت می‌کند؛ متن پاسخ بانک، ترمینال، شماره کاربر، توکن، callback و کلید ثبت نمی‌شوند. کد ناشناخته حتی اگر شبیه متن انگلیسی باشد منتشر نمی‌شود.
- دریافت503 با HTML از پراکسی همچنان می‌تواند پیش از این پاسخ برسد؛ اگر پیام عمومی قبلی بدون کد باقی ماند، Response/لاگ پراکسی لازم است. ادعای حل محیط زنده نشده است.

## آزمون‌ها

PASS npm run check:payments؛ شامل تست جدید callback با PUBLIC_ORIGIN عمومی و پورت داخلی تصادفی، قرارداد wire، خطاهای بانک/HTTP/JSON، timeout/DNS، عدم افشای خطای ناشناخته، مالکیت، CSRF، callback بدون نشست و جلوگیری از شارژ تکراری.

PASS node tests/payments-ui-check.cjs؛ پیش‌فاکتور، دریافت/نمایش کد خطا، فعال‌شدن تلاش دوباره، مسیر انتقال سپ، محدودیت referrer/CSP و اندازه‌های320/390/1366. تصویر محلی: artifacts/payments/sep-token-error.png.

پرداخت واقعی و متغیرهای زندهٔ رانفلر در این جلسه بررسی نشدند. برای تأیید نهایی، نسخهٔ جدید باید مستقر و تلاش بعدی با کد خطای جدید یا انتقال موفق به سپ مشاهده شود.
