# وضعیت حساب محدود یا حذف‌شده

## رفتار کاربر
پس از رمز صحیح، کد پیامکی معتبر یا احراز هویت اجتماعی، حساب محدود به `/account-status/` هدایت می‌شود. این مسیر دادهٔ خصوصی را فقط با مجوز همان پرونده دریافت می‌کند؛ لینک صفحه به‌تنهایی مجوز نیست. برای حساب حذف‌شده، رمز قبلی نگهداری نشده و ورود از کد پیامکی یا هویت اجتماعیِ تأییدشده استفاده می‌کند.

تعلیق دلیل عمومی و پایان مشخص یا «تا بررسی مدیریت» دارد. بازبینی یک تیکت با اولویت بالا در صندوق فعلی پشتیبانی ایجاد می‌کند؛ تکرار درخواست تیکت تکراری نمی‌سازد. پاسخ ساپورت در همین صفحه قابل خواندن است. ساپورت مجوز رفع تعلیق ندارد؛ مدیر دارای دسترسی از مسیر قبلی حساب آن را رفع می‌کند. محدودیت زمان‌دار از نظر سرور پس از پایان قابل رفع است؛ بررسی پس‌زمینه هر ۳۰ ثانیه و بررسی هنگام احراز هویت انجام می‌شود.

حذف، دلیل و شناسهٔ مدیرِ زمان تصمیم را نشان می‌دهد. ثبت‌نام دوباره فقط حسابی تازه و خالی می‌سازد و به داده یا موجودی قدیمی وصل نمی‌شود. فاکتور و اسناد بانکی‌ای که طبق سیاست قبلی برای پیگیری نگه داشته می‌شوند، با حساب تازه جابه‌جا یا شارژ نمی‌شوند.

حذف‌های قبل از این تغییر که سابقهٔ لازم ندارند خودکار بازسازی نشده‌اند؛ دلیل داخلی قدیمی به‌عنوان دلیل عمومی منتشر نمی‌شود. تعلیق‌های قبلی بدون پرونده، توضیح عمومیِ نبود سابقه و امکان بازبینی می‌گیرند. برای تعلیق بدون تاریخ، مدیریت باید آن را صریحاً رفع کند.

## مدیریت و حریم خصوصی
دلیل داخلی و دلیل قابل نمایش جدا هستند. توضیح عمومی باید ۵ تا ۱۰۰۰ نویسه باشد. پایان اختیاری تعلیق باید آینده و حداکثر ده سال باشد. تعلیق گروهی بدون تاریخ پایان است و مدیر از عمومی‌بودن دلیل گروهی مطلع می‌شود.

مهاجرت فقط جداول `account_notices`، `account_notice_identities`، `account_notice_proofs` و `account_notice_key` را اضافه می‌کند. کلید HMAC تصادفی ۳۲ بایتی یک بار در دیتابیس ثبت می‌شود و در API، لاگ و مخزن قرار نمی‌گیرد. اثر هویت برای تشخیص سابقه نگه داشته می‌شود؛ رمز، مشخصات یا توکن ارائه‌دهنده در این سابقه ذخیره نمی‌شوند. زمینهٔ اثبات هویتِ جدید کوتاه‌مدت است و با انقضای مجوز پاک می‌شود.

مجوز وضعیت پانزده دقیقه، HttpOnly، SameSite و روی HTTPS دارای Secure است. نشست‌های موجود هنگام تصمیم، حداکثر پانزده دقیقه برای دیدن دلیل قابل استفاده‌اند، نه برای داشبورد. خروج و شروع ثبت‌نام دوباره مجوز فعلی را مصرف/پاک می‌کند. تمام تغییرهای POST کنترل Origin و JSON دارند. پاسخ وضعیت، کلید HMAC یا زمینهٔ احراز هویت را منتشر نمی‌کند.

## آزمون و پیش‌نمایش
`tests/account-status-check.cjs`: SQL واقعی روی SQLite و HTTP محلی، اثبات رمز/OTP/OAuth، جلوگیری از مشاهدهٔ ناشناس و دسترسی به داشبورد، تفکیک دلیل داخلی، تیکت/پاسخ، CSRF، زمان پایان، تکرار، حذف و ثبت‌نام تازه.

`tests/account-status-ui-check.cjs`: Playwright در عرض ۱۴۴۰، ۳۹۰ و ۳۲۰؛ عکس‌ها در `artifacts/account-status/`. برای فرم مدیر عکس‌های `artifacts/admin-completion/suspend-*.png` ثبت می‌شوند. مسیرهای آزمایشی فقط در سرور fixture محلی‌اند و به تولید اضافه نشده‌اند:
- `/__preview__/account-status/suspended/`
- `/__preview__/account-status/deleted/`

این‌ها اثبات MySQL یا پیامک/OAuth زنده نیستند؛ هیچ پیام یا پرداخت واقعی برای آزمون ارسال نشده است.
