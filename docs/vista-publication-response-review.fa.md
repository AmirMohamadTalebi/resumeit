# بررسی پاسخ انتشار ویستا

## شواهد و محدودیت

- خطای گزارش‌شده از شاخهٔ `INVALID_RESPONSE` مرورگر است: پاسخ غیر JSON یا بدنه‌ای که کامل خوانده و تجزیه نشده است. این پیام به‌تنهایی وضعیت HTTP یا علت خرابی میزبان را مشخص نمی‌کند.
- انتشار اولیه و به‌روزرسانی ویستا با حساب و اشتراک آزمایشی، اطلاعات تماس عمومی و تأیید متن نمونه در سرور محلی موفق بود.
- دسترسی Chrome فعال نبود؛ پاسخ واقعی سایت و گزارش میزبان مشاهده نشده‌اند. آزمایش SQLite و خطای تزریق‌شده جای تشخیص قطعی MySQL یا پراکسی سایت زنده نیست.

## ضعف بازتولیدشده و اصلاح

- قبلاً قطع پاسخ پس از ثبت تراکنش، به کاربر خطا نشان می‌داد و نسخهٔ محلی قدیمی باقی می‌ماند.
- اکنون درخواست انتشار `compact:true` دارد. پاسخ فقط نسخه، نام صفحه و وضعیت انتشار را دارد و تصاویر داخل snapshot به مسیر رسانهٔ خصوصی تبدیل می‌شوند. مصرف‌کنندگان قدیمی همچنان پاسخ کامل می‌گیرند.
- در قطع شبکه یا پاسخ نامعتبر فقط یک GET خواندن سند انجام می‌شود؛ POST انتشار تکرار نمی‌شود.
- موفقیت بازیابی فقط با افزایش دقیق یک واحدی نسخهٔ سند و شمارهٔ انتشار همان نوع صفحه و وضعیت منتشرشده پذیرفته می‌شود. حساب، جایگاه و نسخهٔ محلی نیز باید ثابت مانده باشند.
- تغییرات فرم از پاسخ بازیابی جایگزین نمی‌شوند. خطای بدون ثبت موفق همچنان خطا باقی می‌ماند.

## بررسی محلی

- `tests/vista-publication-recovery-ui-check.cjs`: انتشار/به‌روزرسانی ویستا، صفحهٔ لینک، پاسخ کوچک بدون دادهٔ تصویر، HTML خطای 502 پس از ثبت، JSON بریده‌شده، عدم تکرار POST، رد خطای بدون ثبت و تغییر جایگاه هنگام دریافت پاسخ.
- سایر تست‌های API داشبورد برای پاسخ کامل قدیمی و قرارداد snapshot حفظ شده‌اند.
