R3-a2 (جایگزین، بزرگ): یک استایل‌شیت واحد برای داشبورد، پایان لایه‌های روی‌هم

درست می‌گید، پاک کردن docs محصول رو عوض نمی‌کنه. جایگزینش رو این‌طوره: داشبورد الان ۲۰ فایل CSS داره که static.cjs می‌چسبونه به workspace.css، ≈۴۰۷KB خام (≈۹۱KB gzip) پیش از اینکه هیچ صفحه‌ای رسم بشه، و کنارش ≈۴۵۴KB JS. توش چند «لایهٔ بازنویسی» روی هم نشسته: abgoon.css (۳۱KB، پالت فیروزه‌ای قدیمی که liquid/night با --bro-600 قهوه‌ای روش نوشتن)، liquid، nova و night («loaded after every other style» تو کامنت خودش).

شواهد (با اسکریپت روی همین repo، تقریبی): ≈۴٬۴۰۰ قاعده، که ≈۴۳۵ تاش سلکتور یکسانِ یه فایل قبلیه که دوباره تعریف شده (≈۳۳KB) و ≈۵۳۰ قاعده کلاسی دارن که هیچ‌جا توی dist/dashboard، src یا runtime قالب‌ها نیست (≈۴۶KB؛ abgoon و nova و pages بیشترین). تعداد !important هم ۹۴ تاست، نشونهٔ جنگ بین لایه‌ها.

فازها، هر کدوم تنهایی ارزش دارن: ۱) حذف قاعده‌های مرده با فهرست سلکتور تأییدشده دستی (کلاس‌های ساخته‌شده با الحاق رشته مثل coral-hide-* باید معاف بشن). ۲) تا کردن بازنویسی‌های هم‌سلکتور داخل فایل اصلی‌شون و حذف abgoon.css. ۳) تبدیل liquid/nova/night به یک لایهٔ «theme.css» و یک تست check:ui-layout که اگه قاعدهٔ بی‌صاحب برگرده بشکنه.

نتیجه: حدود ۷۰–۸۰KB خام کمتر روی هر ورود به داشبورد (اینترنت ایران)، و از «چرا این دکمه رنگ اشتباهه» خلاص می‌شیم. حذف ≈۹۰۰ خط، اضافه ≈۶۰ (تست و تا کردن).

ریسک: بصری، یعنی بالاترین. راه‌حل: عکس‌مقایسهٔ check:ui قبل/بعد هر فاز، فقط داشبورد (پیش‌نمایش رزومه و قالب‌ها دست نمی‌خورن)، ترتیب cascade حفظ، فاز ۳ فقط اگه فاز ۱–۲ تمیز بود. پول و داده: صفر. دیپلوی: assetRevision خودش hash می‌گیره.

R3-b (کوچک) دفاع: ادغام @import های admin.css

قبول شد با شرط ترتیب cascade. فایده فقط برای ادمین نیست؛ آبشار @import یعنی تا glass.css و navigation.css نرسن منوی ادمین بی‌استایل رسم می‌شه، و این روی هر صفحهٔ ادمین تکرار می‌شه. هزینه ≈۱۲ خط جابه‌جاشده و دو فایل کمتر، خطر عملاً صفر چون سلکتور و ترتیب عوض نمی‌شن. می‌خوام اضافه کنم که قیاس هم‌اندازه تو داشبورد (R3-a2) همین الگوی «بسته‌ها رو به‌جای زنجیرهٔ درخواست یکی کن» رو ادامه می‌ده، یعنی این کوچیکه یه گام آماده‌سازی خوبه.

R3-c (کوچک) دفاع: حذف test:serial

رضا درست می‌گه که شبیه یک کامیته؛ ولی کامیت‌های بی‌صاحب همین‌طور می‌مونن. این خط الان واقعاً از test عقب مونده (seo-check توش نیست)، یعنی کسی که لوکال serial می‌زنه تست SEO رو بی‌صدا از دست می‌ده. حذفش + یک جملهٔ RI_JOBS=1 تو README یه منبع حقیقت می‌سازه. اگه شورا تصمیم گرفت پیشنهاد جدا نباشه، می‌تونه بره داخل همون کامیت پاکسازی docs.

R3-d (کوچک، بازمانده از R3-a): پاکسازی گزارش‌های docs و تست‌های یتیم

اگر خواستید نگه داریم: ۳۲ گزارش تاریخی docs/ (≈۲٬۲۰۰ خط) و شش تست یتیم (_peek، checkout-response-check، coral-release-check، email-login-ui-check، rail-glass-hover-ui-check، workspace-preview) و refine-satiar/vista. اصلاح الهام: README به HOSTING، AUTH-SETUP، SMSIR، DASHBOARD-IMPLEMENTATION و REVIEW-21.1 لینک داده، همه می‌مونن و فهرست نهایی فایل‌به‌فایل تو spec می‌آد. حذف ≈۲٬۳۰۰ خط، اضافه ≈۳.
