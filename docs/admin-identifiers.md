# شناسه‌های داخلی مدیریت

این کدها ابزار پیدا کردن رکورد در مدیریت‌اند؛ شمارهٔ سند بانکی یا فاکتور نیستند. کلیدهای قبلی، رابطه‌های دیتابیس و آدرس‌های API حفظ شده‌اند.

| موضوع | نمونهٔ الگو |
|---|---|
| حساب مالک | Owner-12 |
| حساب ادمین | Admin-13 |
| حساب ساپورت | Support-14 |
| حساب کاربر | User-15 |
| جایگاه صفحهٔ رزومه/لینک | Page-13 |
| قالب رزومه | Tem-R-14 |
| قالب لینک | Tem-L-15 |
| فونت | Font-16 |
| اشتراک رخش / سیمرغ / هما | Rakhsh-17 / Simorgh-18 / Homa-19 |
| پرداخت بانکی در مدیریت | peycard-20 |
| گردش کیف پول در مدیریت | paywallet-21 |
| تیکت در ساپورت | Tecket-22 |
| رویداد مدیریت | AdminLogs-23 |

اعداد بالا فقط نمونه‌اند. شمارندهٔ جدول `admin_codes` مشترک است، کد در اولین مشاهدهٔ مجاز ثبت می‌شود و شماره‌ها لزوماً پیوسته یا به ترتیب تاریخ ساخت حساب نیستند. قید یکتای نوع/کلید از ایجاد دو شماره برای یک رکورد جلوگیری می‌کند. تغییر نقش پیشوند حساب را عوض می‌کند، نه عدد اصلی؛ حذف رکورد شماره را به شخص دیگری نمی‌دهد. `Rol-...` و پیشوند نقش قبلی برای یافتن ارجاع‌های قدیمی پذیرفته می‌شوند؛ پیشوند جست‌وجو هیچ نقشی اعطا نمی‌کند. سابقهٔ تصمیم مدیریت، شناسهٔ مدیر را در زمان همان تصمیم نگه می‌دارد.

رنگ، دسترسی خریداری‌شده/اعطاشده و رویداد OTP همان شناسهٔ قبلی را دارند. کدها در API عمومی کاتالوگ، تیکتِ کاربر عادی، سند چاپی و دانلود سند مالی اضافه نمی‌شوند. خروجی فهرست مدیریت می‌تواند ستون کد مدیریتی داشته باشد؛ خروجی سند بانکی ندارد.

## نمونهٔ جست‌وجو
- `User-12` یا `شناسه:Admin-13`؛ `Rol-12` نیز برای ارجاع قدیمی پذیرفته می‌شود.
- `کیان مهر نقش:ادمین`
- `اشتراک:Homa` یا `اشتراک:هما`
- `تاریخ:1405/07/24` یا `2026-10-16`؛ بازهٔ همان روز با ساعت تهران.
- `درگاه:زیبال وضعیت:موفق حداقل:50000`؛ مبلغ پرداخت تومان است.
- `User-12 جهت:کاهش` در دفتر کیف پول؛ مبلغ کیف پول It است.
- `محصول:Tem-R-14` در دسترسی‌ها و تراکنش‌ها.
- `Tecket-22` یا `مهر اولویت:بالا دسته:پرداخت` در ساپورت.

چند کلمه با شرط «همهٔ واژه‌ها» ترکیب می‌شوند، نه جست‌وجوی تقریبی یا هوش مصنوعی. کد دقیق سابقهٔ قدیمی و بایگانی را هم می‌یابد؛ فیلترهای صریح و محدودهٔ دسترسی حذف نمی‌شوند. ویژگی نامرتبط به فهرست با خطا رد می‌شود. تاریخ فقط جایی جست‌وجو می‌شود که تاریخ واقعی موجود است؛ برای صفحه‌ها تاریخ ساختِ حدسی ساخته نشده و جست‌وجوی تاریخ با پیام روشن رد می‌شود. جست‌وجوی محصولات در دستهٔ انتخاب‌شده است و نام، کد، توضیح، آخرین ویرایشِ ثبت‌شده و وضعیت/قیمت را بررسی می‌کند.

## تغییر دیتابیس و آزمون
مهاجرت فقط جدول نگاشت را اضافه می‌کند؛ هیچ UUID یا مرجع بانکی بازنویسی نمی‌شود. تست‌های `admin-codes-check`، `admin-filters-check` و `admin-workflow-ui-check` ذخیرهٔ پایدار، رقابت ثبت، تاریخ‌ها، جست‌وجوی ترکیبی، مالکیت و نبود کد در سند بانکی را پوشش می‌دهند. تست محلی SQLite جای آزمون MySQL واقعی یا استقرار زنده نیست.
