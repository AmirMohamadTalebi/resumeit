# پرداخت، پیش‌فاکتور و فاکتور ResumeIt — نسخهٔ ۲۱.۳.۰

## مسیر کاربر

کیف پول ← ورود مبلغ به تومان ← «تأیید مبلغ و مشاهدهٔ پیش‌فاکتور» ← بررسی پیش‌فاکتور و انتخاب سپ یا زیبال ← تأیید مبلغ ← درگاه بانکی ← صفحهٔ نتیجه و فاکتور.

پیش‌فاکتور شامل شناسهٔ یکتا، تاریخ، اطلاعات صاحب حساب، مقدار It و مبلغ است. مبلغ در دیتابیس ثبت می‌شود و درخواست مرورگر نمی‌تواند آن را عوض کند. هر ۲٬۰۰۰ تومان برابر یک It است؛ مبلغ ارسالی به هر دو درگاه به ریال تبدیل می‌شود. پیش‌فاکتور ۲۴ ساعت معتبر است و درخواست بانکی ۲۰ دقیقه برای شروع پرداخت فرصت دارد.

درگاه‌های فعال داخل پیش‌فاکتور قابل انتخاب‌اند. پس از شروع اتصال، همان پیش‌فاکتور به یک درگاه متصل می‌ماند تا پرداخت هم‌زمان با دو درگاه ایجاد نشود. اگر اتصال ناموفق یا درخواست منقضی شد، از کیف پول پیش‌فاکتور تازه صادر کن. درگاه غیرفعال به‌وضوح مشخص است؛ پیش‌فاکتور همچنان قابل مشاهده و چاپ است.

پس از پرداخت، صفحهٔ نتیجه وضعیت واقعی سرور را نشان می‌دهد. فاکتور پرداخت‌شده، مرجع بانکی، کد رهگیری و زمان به‌روزرسانی دارد و از گزینهٔ چاپ می‌توان PDF ذخیره کرد. پارامترهای URL وضعیت موفق ایجاد نمی‌کنند. فاکتور و رسید نیز از تاریخچهٔ کیف پول قابل پیگیری هستند.

## تنظیمات سرور

در متغیرهای محرمانهٔ سرویس Node در رانفلر:

```dotenv
PUBLIC_ORIGIN=https://resumeit.ir
SEP_ENABLED=false
SEP_TERMINAL_ID=
ZIBAL_ENABLED=false
ZIBAL_MERCHANT_ID=
```

سپ: تأیید پذیرندگی، ترمینال معتبر و ثبت IP عمومی **خروجی سرور** نزد سپ لازم است. راهنمای جزئی در [SEP-PAYMENTS.fa.md](SEP-PAYMENTS.fa.md) قرار دارد.

زیبال: شناسهٔ پذیرندهٔ تأییدشده را از پنل زیبال در متغیر `ZIBAL_MERCHANT_ID` وارد کن؛ سپس `ZIBAL_ENABLED=true`. مقدار آزمایشی `zibal` برای فعال‌کردن سایت تولید پذیرفته نمی‌شود. هیچ شناسهٔ محرمانه‌ای در صفحات یا فهرست مدیر نمایش داده نمی‌شود.

آدرس‌های بازگشت قابل ثبت:

```text
https://resumeit.ir/api/payments/sep/callback
https://resumeit.ir/api/payments/zibal/callback
```

هر دو آدرس بدون پارامتر، صفحهٔ آماده‌بودن مسیر را نمایش می‌دهند. سرور در هر درخواست، شناسهٔ محرمانهٔ سفارش را به آدرس بازگشت اضافه می‌کند. این نشانی‌ها برای ارسال یا دریافت شماره و رمز کارت نیستند.

## تأیید و رسیدگی به اختلال

سپ با پروتکل REST مستند نسخهٔ ۳.۶ آماده شده است. زیبال بر اساس [مستندات رسمی](https://help.zibal.ir/ipg/) و [OpenAPI رسمی](https://api.zibal.ir/static/helpdocs/ipg.json)، از `request`، `inquiry` و `verify` استفاده می‌کند. پاسخ استعلام یا تأیید باید به شناسهٔ سفارش و مبلغ همان پیش‌فاکتور مربوط باشد.

برای زیبال، شناسهٔ درخواست در دیتابیس نگهداری می‌شود و استعلام دوره‌ای می‌تواند نتیجه را حتی بدون بازگشت مرورگر بازیابی کند. درخواست هنوز پرداخت‌نشده، اعتبار ایجاد نمی‌کند. پرداخت تأییدشده یا پاسخ «قبلاً تأیید شده» با استعلام معتبر بازیابی می‌شود. سپ برای بازیابی پس از قطع اتصال از رسید ذخیره‌شده استفاده می‌کند؛ بدون دریافت رسید، استعلام صرفاً با شمارهٔ سفارش در این پروتکل پیاده‌سازی نشده است.

شارژ، سند کیف پول و وضعیت پرداخت، یک تراکنش MySQL هستند. شناسهٔ یکتای رسید و قفل موقت بررسی، جلوی شارژ تکراری و هم‌زمان را می‌گیرند. درخواست‌های جدید محدودیت تعداد دارند. قطع اتصال یا ری‌استارت سرور، درخواست ثبت‌شده را حذف نمی‌کند. خاموش‌کردن درگاه، ایجاد پرداخت تازه را متوقف می‌کند؛ رسیدگی به پرداخت‌های قبلی ادامه دارد.

مغایرت مبلغ یا حذف حساب در زمان تأیید، اعتبار ایجاد نمی‌کند. در سپ درخواست برگشت ارسال می‌شود؛ برگشت تأییدنشده نیازمند پیگیری است. API درگاه زیبالِ استفاده‌شده، پایانهٔ برگشت وجه با کلید پذیرنده ندارد؛ این موارد با کد `REFUND_REQUIRED_*` در پنل مدیریت ثبت می‌شوند و باید از قابلیت استرداد پنل زیبال یا پشتیبانی آن پیگیری شوند. سایت ادعای برگشت موفق نمی‌کند.

پنل مدیریت ← پرداخت‌های بانکی: درگاه، مبلغ، وضعیت، شمارهٔ مرجع، کد رهگیری، تعداد بررسی و کد خطا. اطلاعات کارت و پاسخ خام بانک ذخیره یا نمایش داده نمی‌شوند. با حذف حساب، اتصال پیش‌فاکتور و سفارش مالی به حساب قطع می‌شود؛ سوابق مالی برای پیگیری باقی می‌مانند.

## بررسی پیش از فعال‌سازی واقعی

تست قرارداد هر دو درگاه، حفاظت پیش‌فاکتور، ثبت هم‌زمان پول، تکرار رسید، قطع اتصال، لغو، مغایرت و صفحهٔ موبایل با درگاه ساختگی بررسی می‌شوند. تست MySQL روی دیتابیس موقت جدا انجام می‌شود.

```text
npm run check:payments
npm run check:database
node tests/payments-ui-check.cjs
```

قبل از اعلام فعال‌بودن، یک پرداخت واقعی کم‌مبلغ برای هر درگاه با رضایت صاحب کارت انجام بده و مبلغ ریالی بانک، شارژ دقیق It، رسید و گزارش مدیر را تطبیق بده. در این مرحله هیچ پرداخت واقعی انجام نشده است. تنظیمات را فقط بعد از تأیید پذیرندگی و تطبیق قرارداد اختصاصی سپ فعال کن.
