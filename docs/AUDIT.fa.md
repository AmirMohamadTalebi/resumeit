# بررسی ResumeIt — ۱۱ اکتبر ۲۰۲۶

این پروژه یک لندینگ فارسی، نمونه‌های رزومه و لینک‌ها، و ورود و داشبورد نمایشی است. بار فرض‌شده، بازدیدکنندگان یک سایت استاتیک و یک کاربر نمایشی در هر مرورگر است؛ هیچ سرور احراز هویت، پرداخت یا پایگاه داده‌ای در نسخهٔ منتشرشده وجود ندارد.

هیروی Signature روی صفحهٔ اصلی ادغام شد. CSS و JavaScript آن با `/signature/` مشترک است؛ فاصلهٔ لازم برای منوی ثابت در `dist/signature/integration.css` قرار دارد. هم‌پوشانی کارت‌ها با منو در ادغام اصلاح شد.

## موارد لازم برای اصلاح

۱. **فیلدهای فقط شامل فاصله، ذخیره می‌شوند** — `dist/dashboard.js:10,12`

- کار این کد: معرفی شخص و عنوان لینک را از فرم به پیش‌نویس منتقل می‌کند.
- مشکل: `required` رشتهٔ چند فاصله را می‌پذیرد؛ بعد `trim()` آن را خالی می‌کند. در نتیجه معرفی خالی ذخیره می‌شود یا لینک بدون عنوان و بدون متن قابل دسترسی ساخته می‌شود.
- راه‌حل کوچک: بعد از trim، مقدار خالی را رد کند و خطای همان فیلد را نمایش دهد.
- اگر اصلاح نشود: کاربران می‌توانند ناخواسته لینک بی‌نام یا معرفی خالی بسازند.

۲. **پیشرفت تکمیل هرگز ۱۰۰٪ نمی‌شود** — `dist/dashboard.js:8` و `dist/dashboard/index.html:2`

- کار این کد: درصد تکمیل سه مرحله را نمایش می‌دهد.
- مشکل: فقط دو شرط `hasProfile` و `hasLinks` وجود دارد، ولی حاصل بر سه تقسیم می‌شود؛ بیشینه ۶۷٪ است. مرحلهٔ ظاهر هیچ وضعیت انتخاب و تکمیل ندارد.
- راه‌حل کوچک: تا زمان پیاده‌سازی انتخاب ظاهر، درصد را بر دو مرحلهٔ فعال محاسبه کند و مرحلهٔ ظاهر را صریحاً نمایشی معرفی کند.
- اگر اصلاح نشود: کاربر دو کار موجود را تمام می‌کند، ولی پیشرفت همچنان ناقص می‌ماند.

## موارد بهتر است اصلاح شوند

۳. **خروج، پیش‌نویس شخصی را پاک نمی‌کند** — `dist/auth.js:34` و `dist/dashboard.js:2,4,7`

- کار این کد: پرچم ورود را در sessionStorage و پیش‌نویس را در localStorage نگه می‌دارد.
- مشکل: خروج فقط پرچم ورود را حذف می‌کند. نفر بعدی در همان پروفایل مرورگر می‌تواند با ورود نمایشی، نام، معرفی و لینک‌های نفر قبل را ببیند؛ داده به حساب یا شماره‌ای تعلق ندارد.
- راه‌حل کوچک: توضیح این رفتار را در بخش حریم خصوصی بیاورد و امکان پاک‌کردن پیش‌نویس محلی بدهد. اتصال داده به حساب باید هنگام ساخت احراز هویت واقعی انجام شود.
- اگر اصلاح نشود: روی مرورگر مشترک، اطلاعاتی که کاربر در دمو وارد کرده باقی می‌مانند. این یافته به‌معنای نشت داده از سرور نیست.

۴. **دو تست قدیمی با رابط فعلی ناسازگارند** — `check.cjs:3` و `motion-check.cjs:2`

- کار این فایل‌ها: چک‌های قدیمی رابط و انیمیشن را اجرا می‌کنند.
- مشکل: check انتظار دارد دکمهٔ ورود dialog باز کند، در حالی که به `/login/` می‌رود. motion-check دنبال `.resume-preview` و pin قدیمی ScrollTrigger است؛ هیروی فعلی از این عناصر استفاده نمی‌کند.
- راه‌حل کوچک: از `hero-check.cjs` برای چک کوتاه فعلی استفاده شود و توقع‌های قدیمی هنگام نیاز واقعی به آن تست‌ها به‌روز شوند.
- اگر اصلاح نشود: اجرای مجموعهٔ قدیمی خطاهای مربوط به رابط حذف‌شده می‌دهد و نتیجهٔ آن گمراه‌کننده است. این تست‌های قدیمی در این درخواست اجرا نشدند.

۵. **کد و CSS مربوط به تجربه‌های کنارگذاشته‌شده باقی مانده‌اند** — `dist/hero.js`، `dist/hero.css` و `dist/experience.css:4–9,49–70`

- کار این فایل‌ها: هیروی قبلی و لایه‌های particle قبلی را سبک‌دهی و کنترل می‌کنند.
- مشکل: صفحهٔ اصلی اکنون فایل‌های Signature را بارگذاری می‌کند؛ `hero.js` و `hero.css` مصرف‌کنندهٔ HTML ندارند. قوانین particle در experience.css نیز با وجود حذف markup و script مربوط، همچنان همراه قوانین لازمِ گالری بارگذاری می‌شوند.
- راه‌حل کوچک: هیروی قدیمی را پس از بایگانی تغییر محلی قبلی حذف کند و فقط قوانین particle بدون مصرف‌کننده را از experience.css بردارد؛ کل experience.css حذف نشود، چون گالری به آن وابسته است.
- اگر اصلاح نشود: اصلاح ظاهر سخت‌تر می‌شود و مرورگر CSS بی‌مصرف می‌گیرد. تغییر محلی قبلی `hero.css` در این کار حذف یا بازنویسی نشد.

## امنیت و ساختار

- در کدهای اختصاصی خوانده‌شده، رمز عبور به localStorage، sessionStorage یا سرور فرستاده نمی‌شود. ورود با هر رمز واجد طول لازم و OTP نمایشی `123456` عمدی است و نقش امنیت واقعی ندارد.
- دادهٔ داشبورد با `textContent` نمایش داده می‌شود؛ URL لینک‌ها فقط `http:` و `https:` را می‌پذیرد و لینک پنجرهٔ جدید `noopener noreferrer` دارد. دادهٔ خوانده‌شده از localStorage نیز محدود و اعتبارسنجی می‌شود.
- `innerHTML` نمونهٔ رزومه از دادهٔ ثابت و theme دارای فهرست مجاز ساخته می‌شود؛ پارامتر آزاد query مستقیماً وارد markup نمی‌شود. این بررسی سورس است، نه تست نفوذ.
- تقسیم فعلی به auth، dashboard، demo و signature برای این مرحله مناسب است. `app.js` به DOM صفحهٔ اصلی وابسته است و نباید به‌عنوان ماژول مشترک صفحات دیگر بارگذاری شود. نیازی به افزودن framework یا dependency نیست.
- نسخهٔ مستقل `ResumeIt-Node/` نیز از روی سورس بررسی شد: سرور فقط GET/HEAD می‌پذیرد، مسیر و realpath را محدود می‌کند و nosniff می‌فرستد. این پوشه یک نسخهٔ مستقل با ظاهر و تولیدکنندهٔ جداست، در Git سایت نادیده گرفته می‌شود و در این انتشار تغییر نکرد.

## اعتبارسنجی انجام‌شده

مطابق خواستهٔ کاربر، فقط چک کوتاه مرورگر Edge اجرا شد: پاسخ ۲۰۰ صفحهٔ اصلی، یک H1، هشت کارت، تغییر موقعیت کارت با اسکرول، و نبود خطای runtime در همین مسیر. تصاویر شروع و پایان حرکت بازبینی شدند. چک کوتاه پاس شد.

مجموعهٔ گستردهٔ تست مرورگر متوقف شد. مسیرهای کامل ثبت‌نام، بازیابی، داشبورد، موبایل، Safari، تست نفوذ، تست بار، امنیت زیرساخت میزبان و ممیزی داخلی کتابخانه‌های vendor بررسی اجرایی نشدند. خطای دسترسی شبکه اجازهٔ اجرای self-check سرور Node در sandbox را نداد؛ این چک تکرار نشد.

نتیجه: ادغام هیرو آمادهٔ انتشار است. برای بهبود رفتار دمو، اول اعتبارسنجی فیلد خالی و درصد پیشرفت اصلاح شوند؛ برای استفاده از دادهٔ واقعی، احراز هویت و جداسازی دادهٔ کاربران لازم است.

کاهش قابل انجام: حدود ۴۰ خط JavaScript هیروی قبلی و CSS بدون مصرف‌کننده؛ هیچ وابستگی تازه‌ای اضافه نشد.

وضعیت انتشار این درخواست: سورس ادغام با commit 6e7a93d44decef0c2feddec700efc32d6aad7a3c به مخزن سایت push شد و بستهٔ hero-update.tar.gz ساخته شد. فراخوانی ذخیره و بازیابی نسخهٔ Sites با خطای اتصال به سرویس شکست خورد؛ انتشار آنلاین تأیید یا انجام نشده است.

## اصلاحات بعد از درخواست کاربر برای رفع ایرادها

یافته‌های بالا سابقهٔ ممیزی‌اند. اعتبارسنجی فیلدهای ضروری، ورود فقط فاصله را رد می‌کند؛ درصد پیشرفت دو مرحلهٔ واقعاً قابل ذخیره را حساب می‌کند و به ۱۰۰٪ می‌رسد. خروج از دمو با تأیید کاربر پیش‌نویس را پاک می‌کند؛ رد تأیید، داده و نشست را حفظ می‌کند. این پاک‌سازی فقط دادهٔ demo همین مرورگر را شامل می‌شود.

دو چک قدیمی به چک کوتاه هیروی فعلی هدایت شدند. فایل‌های هیروی قبلی با حفظ نسخهٔ محلی در `artifacts/retired-hero` حذف شدند و قوانین particle بدون مصرف‌کننده از CSS مشترک حذف شدند.

سرور مستقل جدید در ریشهٔ پروژه، همین `dist` فعلی را سرو می‌کند؛ خروجی قدیمی `ResumeIt-Node` بازنویسی نشد. دیتابیس کاربران، پروفایل و لینک‌ها آماده شده است، اما هیچ API عمومی یا اتصال ورود نمایشی به آن وجود ندارد. جزئیات محدودیت اجرا و بکاپ در `HOSTING.fa.md` آمده است.

چک کوتاه دیتابیس برای ماندگاری، جدا بودن رکورد کاربران و رد ورودی نامعتبر پاس شد. اجرای سایت روی سرور مستقل با پاسخ ۲۰۰ و حرکت کارت‌های هیرو هنگام اسکرول و بدون خطای runtime در این مسیر پاس شد. این اصلاحات محلی‌اند؛ روی هاست عمومی منتشر نشده‌اند. اتصال پیامک و نشست واقعی هنوز انجام نشده است.
