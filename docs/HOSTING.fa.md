# اجرای ResumeIt روی هاست خودمان

نسخهٔ فعلی `dist` با `npm start` اجرا می‌شود. Node.js نسخهٔ 24.15 یا جدیدتر لازم است. برای اتصال به MySQL وابستگی mysql2 با npm ci نصب می‌شود. دیتابیس در سرویس جداگانهٔ MySQL روی هاست است.

روی هاست متغیرهای `HOST=0.0.0.0` و `PORT` را مطابق راهنمای همان سرویس تنظیم کنید. اتصال عمومی باید پشت HTTPS باشد. اتصال با MYSQL_HOST، MYSQL_PORT، MYSQL_DATABASE، MYSQL_USER و MYSQL_PASSWORD تنظیم می‌شود. فقط از آدرس داخلی دیتابیس استفاده کنید؛ دسترسی عمومی لازم نیست.

اسکیما شامل کاربران با شمارهٔ یکتا، پروفایل و لینک‌های مرتب است. ذخیرهٔ پروفایل و لینک‌ها در یک تراکنش انجام می‌شود؛ همهٔ پرس‌وجوها پارامتری هستند. ورود با شماره و رمز از نشست معتبر سرور استفاده می‌کند. حساب فعلی به درخواست مالک دستی ساخته می‌شود؛ این کار به معنی تأیید پیامکی شماره نیست.

ورود با رمز واقعی است: رمز با scrypt و salt تصادفی ذخیره می‌شود؛ نشست هفت‌روزه در MySQL و کوکی HttpOnly و SameSite=Lax است. اتصال عمومی HTTPS کوکی Secure دارد. ورود و خروج فقط درخواست JSON از مبدأ سایت را می‌پذیرند. پنج تلاش برای هر شماره در ۱۵ دقیقه مجاز است. شمارندهٔ تلاش‌ها در MySQL است و بین نمونه‌های سرور مشترک می‌ماند.

داشبورد، پیش‌نویس و نسخهٔ منتشرشده در MySQL ذخیره می‌شوند. نام صفحه یکتا و ذخیره دارای کنترل نسخه است. رزومه و صفحهٔ لینک روی زیردامنهٔ کاربر منتشر می‌شوند. ثبت‌نام، بازیابی رمز و ورود پیامکی به سرویس پیامک وصل‌اند؛ OAuth گوگل و گیت‌هاب به تنظیمات هاست نیاز دارد. درگاه پرداخت بانکی غیرفعال است؛ خرید با اعتبار موجود It از کیف پول انجام می‌شود.

از نسخهٔ ۲۱٫۱ کد مشترک داشبورد در زمان راه‌اندازی سرور به دو بستهٔ حافظه‌ای تبدیل می‌شود؛ فایل‌های منبع مستقل‌اند و ابزار build اضافه لازم نیست. صفحات داخلی فقط ماژول همان صفحه را هنگام نیاز دریافت می‌کنند. پس از تغییر فایل‌ها، فرایند Node را دوباره راه‌اندازی کنید تا نسخه و بسته‌ها تازه شوند. PUBLIC_ORIGIN=https://resumeit.ir و wildcard HTTPS برای زیردامنه‌ها لازم‌اند.

MySQL حساب‌ها و نشست‌ها را بین نمونه‌های سرور مشترک نگه می‌دارد. دیتابیس باید دیسک دائمی و بکاپ فعال داشته باشد.

بکاپ MySQL را با ابزار رسمی mysqldump یا امکانات هاست بگیرید و بازیابی آن را بررسی کنید.

بررسی کوتاه: `npm run check:database` ماندگاری پس از بازگشایی، جدا بودن رکورد کاربران و رد ورودی نامعتبر بدون خراب کردن دادهٔ ذخیره‌شده را بررسی می‌کند. تست بار و پیامک واقعی هنوز انجام نشده است.

## ساخت حساب دستی

`node scripts/provision-account.cjs` یک خط JSON با کلیدهای `phone` و `password` از ورودی استاندارد می‌گیرد. رمز وارد کد، گیت یا خروجی برنامه نمی‌شود. شمارهٔ موجود با رمز موجود بازنویسی نمی‌شود. برای ساخت حساب در اولین استقرار می‌توان `BOOTSTRAP_PHONE` و `BOOTSTRAP_PASSWORD_HASH` را در تنظیمات هاست گذاشت؛ مقدار دوم فقط هش scrypt معتبر است. پس از ساخت حساب، این دو متغیر را حذف کنید. `PUBLIC_ORIGIN` برای production و اتصال عمومی اجباری است؛ مبدأ HTTPS سایت را بدون مسیر، query یا fragment تنظیم کنید. در توسعهٔ محلی فقط localhost و 127.0.0.1 مجازند.

`npm run check:auth` هش رمز، ورود و خروج، انقضای نشست، کنترل مبدأ، حفاظت داشبورد و محدودیت تلاش را با مخزن ساختگی بررسی می‌کند؛ بررسی MySQL واقعی با check:database است.

## انتقال از SQLite

برای اولین اجرا SQLITE_MIGRATION_PATH را به فایل قبلی روی دیسک دائمی تنظیم کنید. انتقال، فایل قبلی را فقط می‌خواند و شناسه‌ها، هش رمز، پروفایل، لینک‌ها و نشست‌های فعال را در یک تراکنش وارد MySQL می‌کند. اجرای تکراری حساب را بازنویسی نمی‌کند و اختلاف شناسه یا رمز را رد می‌کند. بعد از تأیید ورود، این متغیر را حذف کنید. فایل قبلی تا تأیید بکاپ برای بازگشت نگه داشته می‌شود و دیگر دیتابیس فعال سایت نیست.

npm run check:database یک دیتابیس موقت مستقل می‌سازد و پس از بررسی ماندگاری، تراکنش‌ها، نشست، تلاش‌های هم‌زمان و انتقال تکراری حذفش می‌کند؛ دادهٔ اصلی را تغییر نمی‌دهد. این تست به دسترسی ایجاد دیتابیس موقت نیاز دارد.

فایل‌های ثابت dist از نسخهٔ ۲۱٫۱٫۱ کش محتوای سرور با سقف ۳۲ مگابایت هم دارند؛ بعد از تغییر یا جایگزینی آن‌ها فرایند Node را restart کنید. دسترسی فایل‌های داشبورد و مدیریت پیش از استفاده از کش کنترل می‌شود.

## پروکسی، محدودیت‌ها و لاگ

- اگر Node پشت nginx، LiteSpeed یا Passenger اجرا می‌شود، `TRUST_PROXY=1` (به تعداد پروکسی‌ها) را تنظیم کنید. بدون آن همهٔ بازدیدکننده‌ها یک IP دارند و محدودیت ورود و پیامک برای کل سایت اعمال می‌شود. وقتی Node مستقیم در اینترنت است مقدار را 0 بگذارید تا هدر `X-Forwarded-For` جعلی پذیرفته نشود.
- `OWNER_PHONE` فقط وقتی هنوز مالکی وجود ندارد، شمارهٔ تأییدشدهٔ مالک اول را تعیین می‌کند.
- `SMS_DAILY_LIMIT` سقف روزانهٔ پیامک OTP کل سایت است (پیش‌فرض ۱۰۰).
- `SMS_PHONE_DAILY_LIMIT` سقف روزانهٔ کد برای هر شماره است (پیش‌فرض ۸، بین ۳ تا ۵۰). هر شبکه هم در ۱۵ دقیقه حداکثر ۱۰ کد می‌گیرد؛ پشت Traefik یا nginx بدون `TRUST_PROXY` همهٔ کاربران یک نشانی دارند و این سقف عملاً برای کل سایت مشترک می‌شود. پیام هر محدودیت جداگانه به کاربر نشان داده می‌شود.
- اگر SMS.ir پیامک را نپذیرد، یک خط JSON با `event:"sms_failed"` و کد پاسخ (مثلاً `SMSIR_HTTP_401_STATUS_0` برای کلید نامعتبر یا `SMSIR_CONFIG` برای تنظیم ناقص) در لاگ ثبت می‌شود؛ شماره و متن پیامک ثبت نمی‌شوند.
- `HSTS_INCLUDE_SUBDOMAINS=true` را فقط وقتی فعال کنید که همهٔ زیردامنه‌ها HTTPS دارند.
- خطاهای پیش‌بینی‌نشده به‌صورت یک خط JSON با `event:"request_failed"` در stderr ثبت می‌شوند؛ متن خطای دیتابیس و query string (مثل کلید بازگشت پرداخت) ثبت نمی‌شود.
- تصویرهایی که کاربر با آدرس HTTPS خارجی وارد می‌کند، هنگام ذخیره یا انتشار روی سرور دانلود و داخل خود سایت ذخیره می‌شوند تا بازدیدکننده‌ها به سایت دیگری وصل نشوند. دانلود فقط از HTTPS روی پورت ۴۴۳ و آدرس‌های عمومی انجام می‌شود (IP داخلی، localhost و شبکهٔ خصوصی مسدود است)، حداکثر ۲٫۵ مگابایت و ۸ ثانیه، و فقط PNG، JPEG یا WebP پذیرفته می‌شود. سرور باید اجازهٔ اتصال خروجی HTTPS داشته باشد.
- تصویرهای خارجی که قبلاً ذخیره شده‌اند، چند ثانیه بعد از هر بار شروع سرور در پس‌زمینه کپی می‌شوند (`LOCALIZE_EXTERNAL_IMAGES=false` این کار را خاموش می‌کند). نتیجه با `event:"external_images_localized"` در لاگ ثبت می‌شود؛ آدرسی که دیگر در دسترس نیست دست نمی‌خورد.
- تصویرهای داشبورد در جدول جدای `dashboard_media` (به ازای هر حساب و هش محتوا) نگه داشته می‌شوند و سند صفحه فقط آدرس آن‌ها را دارد؛ برای همین بازکردن داشبورد و ذخیرهٔ خودکار دیگر بایت‌های تصویر را نمی‌خوانند و نمی‌نویسند. جدول در شروع سرور خودکار ساخته می‌شود و حدود ۲ ثانیه بعد، تصویرهایی که هنوز داخل سندها مانده‌اند در پس‌زمینه به آن منتقل می‌شوند (تکرارش بی‌خطر است و شمارهٔ نسخهٔ سند عوض نمی‌شود). نتیجه با `event:"dashboard_media_moved"` در لاگ ثبت می‌شود. تصویری که هیچ صفحه‌ای از حساب دیگر استفاده نمی‌کند علامت می‌خورد و اگر ۲۴ ساعت بی‌استفاده بماند، در پاک‌سازی ساعتی حذف می‌شود؛ با حذف حساب، تصویرهایش هم حذف می‌شوند. پیش از اولین اجرای این نسخه از دیتابیس پشتیبان بگیرید.
- جدول `sessions` سه ستون تازه (`created_at`، `last_seen`، `user_agent`) می‌گیرد که در شروع سرور خودکار اضافه می‌شوند. کاربر در «تنظیمات › ورود و امنیت» دستگاه‌های فعال را می‌بیند و می‌تواند هر نشست یا همهٔ نشست‌های دیگر را ببندد.
