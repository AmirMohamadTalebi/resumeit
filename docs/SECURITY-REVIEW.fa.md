# بررسی امنیت و ساختار ResumeIt — ۱۲ اکتبر ۲۰۲۶

مبنای بررسی مخزن خصوصی `VY1-pick/resumeit`، شاخهٔ `main` در commit `1ef6b3118a39dfaec37ed0490faee3b3b2ab72f4` است. GPT Sites در این کار استفاده نشده است. بررسی فایل‌ها، منطق سرور، پرس‌وجوهای دیتابیس، احراز هویت و صفحات مرورگر انجام شد؛ این گزارش ادعای نبود همهٔ آسیب‌پذیری‌های ممکن نیست.

## موارد اصلاح‌شده

| مورد | تغییر |
| --- | --- |
| دور زدن کنترل مسیر داشبورد | رد مسیرهای دو اسلش، dot-segment، backslash، کاراکتر کنترلی، ADS و نام‌های با نقطه یا فاصلهٔ آخر؛ بررسی ورود روی مسیر decode‌شده و مسیر واقعی فایل، شامل case alias و symlink |
| سرو فایل ناخواسته | محدودکردن سرو به نوع‌های فایل عمومی مشخص؛ رد dotfile و خروج از ریشهٔ واقعی `dist` |
| هدرهای مرورگر | CSP بدون `unsafe-inline` برای script و بدون `unsafe-eval`؛ hash اسکریپت‌های درون فایل HTML مورد اعتماد؛ ممنوعیت object و base؛ nosniff، no-referrer، Permissions-Policy، ضد iframe و HSTS در HTTPS |
| گالری صفحهٔ اصلی | فقط `/demo/` اجازهٔ iframe از همان مبدأ دارد؛ حساب و داشبورد قابل embed نیستند |
| اعتماد به Host و تنظیم مبدأ | `PUBLIC_ORIGIN` برای production و اجرای عمومی اجباری و اعتبارسنجی‌شده است؛ fallback فقط در توسعهٔ loopback؛ بررسی Origin درخواست‌های تغییردهنده باقی است |
| ورودی JSON | یک خوانندهٔ مشترک با سقف ۲۰۴۸ بایت؛ رد JSON خراب، null، آرایه و primitive با پاسخ کنترل‌شده |
| خطای خارج از handler | خطای async کنترل و پاسخ عمومی داده می‌شود؛ جزئیات دیتابیس به کاربر برنمی‌گردد |
| مصرف منابع HTTP | timeout هدر/درخواست/سوکت، سقف هدر و سقف تعداد درخواست روی سوکت |
| هش رمز نامعتبر | قالب هش اعتبارسنجی می‌شود؛ مقایسهٔ ثابت‌زمان و scrypt با هش جایگزین برای حساب ناموجود/هش خراب حفظ شد |
| افشای صریح وجود حساب | درخواست کد ورود، بازیابی و درخواست اتصال شماره، پاسخ عادی بدون افشای ثبت بودن شماره می‌دهد؛ برای موارد نامعتبر پیامک ارسال نمی‌شود. این تغییر آزمون مقاومت در برابر تحلیل زمان پاسخ نیست |
| وابستگی proof به حساب | OTP ورود و بازیابی به شناسهٔ مالک اولیه وابسته است؛ reset حساب را با شناسه و شماره قفل می‌کند؛ ایجاد نشست تغییر هم‌زمان رمز و شماره را بررسی می‌کند |
| تغییر شماره | مجوزهای شمارهٔ قبلی و نشست‌های دیگر باطل می‌شوند؛ نشست جاری حفظ می‌شود |
| ثبت‌نام | هش مورد انتظار در ساخت نشست اولیه هم بررسی می‌شود |
| تزریق در رابط | عنوان مودال به صورت متن نمایش داده می‌شود؛ تصویر و gradient قبل از ساخت CSS بررسی می‌شوند؛ SVG آپلودی مجاز نیست؛ ابعاد و قابلیت decode تصویر بررسی می‌شوند |
| پیش‌نویس خراب | ساختار، نوع‌ها، اندازهٔ فیلدها، فهرست‌ها، شناسه‌ها و section پیش از بازیابی بررسی می‌شوند؛ خطا حالت جاری را خراب نمی‌کند |
| تغییر رمز نمایشی | دکمهٔ تنظیمات به بازیابی واقعی با OTP متصل شد؛ دیگر رمز نمایشی جمع‌آوری یا موفقیت ساختگی اعلام نمی‌شود |
| فایل بلااستفاده | `dist/auth.js` و `dist/auth.css` قدیمی حذف شدند؛ فرم‌های فعلی از `dist/auth-ui/` استفاده می‌کنند |

## ساختار

`server.cjs` نقطهٔ شروع و تنظیمات اجراست. `src/http/` مسیر، سرو فایل، محافظت مرورگر و JSON؛ `src/auth/` رمز، احراز هویت، OAuth و OTP؛ `src/database/` اتصال و تراکنش، اسکیما، حساب، OTP، نشست، پروفایل و مهاجرت؛ `src/services/` اتصال SMS.ir؛ `tests/` تست‌ها و fixture؛ `scripts/` ابزار ساخت حساب؛ `docs/` مستندات.

صفحات داشبورد همان مسیرهای مستقل قبلی را دارند. فایل تکراری آیکن‌های نوار بالا در `dist/dashboard/js/toolbar.js` مشترک شده است. مسیر require، دستورهای npm و مستندات به ساختار جدید وصل‌اند. Playwright مورد استفادهٔ تست‌ها به‌عنوان وابستگی توسعه ثبت شده؛ مسیر مطلق کامپیوتر از تست‌ها حذف شده است. CI حداقل دسترسی read دارد و امنیت، مرورگر و دیتابیس آزمایشی MySQL را بررسی می‌کند. ZIP، فایل کلید و دیتابیس محلی در ignore هستند.

## نتیجهٔ بررسی محلی

- بررسی syntax تمام ماژول‌ها، اسکریپت‌ها و تست‌ها: موفق.
- security: مسیرهای دستکاری‌شده، ورود، JSON، Host، CSP، خطا، URL/تصویر، پیش‌نویس خراب و binding دیتابیس: موفق.
- auth، SMS.ir/OTP، OAuth: موفق؛ پیامک و ارائه‌دهندهٔ OAuth شبیه‌سازی شدند.
- dashboard، auth UI، mobile، motion و site content: موفق در Edge؛ عرض‌های دسکتاپ و موبایل، صفحه‌های مستقل، CRUD لینک، پیش‌نویس، ورود/ثبت‌نام/بازیابی، تعامل لمس شبیه‌سازی‌شده و reduced motion.
- `npm audit --omit=dev`: صفر آسیب‌پذیری ثبت‌شده در وابستگی‌های اجرا؛ نصب وابستگی‌های توسعه نیز صفر آسیب‌پذیری گزارش کرد.
- MySQL محلی: `ECONNREFUSED`؛ آزمون SQL واقعی محلی عبور نکرد. تست‌های fixture و کنترل binding، جایگزین تأیید رفتار تراکنش MySQL نیستند. نتیجهٔ CI باید جداگانه بررسی شود.
- MySQL واقعی در GitHub Actions: آزمون `check:database` با MySQL 8.4 در اجرای commit `176ba9fce8899b366c88b7b756ac504930072a86` موفق بود؛ شامل proof، نشست، تغییر شماره و مهاجرت. این نتیجه تأیید دیتابیس هاست نیست.

## مرزها و شرایط اجرا

این تغییرات دادهٔ واقعی کاربران را مهاجرت یا حذف نکرده‌اند و روی هاست منتشر نشده‌اند. ورود حساب، نشست، OTP و OAuth سمت سرور هستند؛ رزومهٔ داشبورد همچنان فقط پیش‌نویس همان تب است. انتشار عمومی، دامنه، پرداخت، entitlement و آمار هنوز سرویس تولیدی ندارند؛ دسترسی و خرید نباید به حالت مرورگر اعتماد کنند. محدودیت ارسال و ورود از IP سوکت استفاده می‌کند؛ هدر Forwarded یا X-Forwarded-For بدون تعریف proxy مورد اعتماد پذیرفته نمی‌شود. پشت proxy مشترک ممکن است سهمیهٔ IP بین کاربران مشترک شود.

تست بار/DDoS، دستگاه موبایل واقعی، تحویل پیامک واقعی، تنظیمات OAuth و HTTPS هاست، نسخهٔ MySQL هاست و دسترسی‌ها/backup آن در این نوبت تأیید نشده‌اند. برای اجرای عمومی `NODE_ENV=production`، `PUBLIC_ORIGIN` صحیح، MySQL داخلی با حساب محدود و secrets خارج از گیت لازم است. پس از انتشار، ورود واقعی و همهٔ مسیرها باید روی دامنهٔ واقعی بررسی شوند.
