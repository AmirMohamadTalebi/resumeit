# SMS.ir و ورود پیامکی

ارسال کد از API `/v1/send/verify/` با قالب تأییدشدهٔ `357964` و متغیر `CODE` انجام می‌شود. انتخاب شمارهٔ فرستنده با SMS.ir است؛ متغیر قدیمی SMSIR_LINE_NUMBER استفاده نمی‌شود.

```dotenv
SMSIR_API_KEY=
SMSIR_TEMPLATE_ID=357964
SMSIR_CODE_PARAMETER=CODE
```

کلید فقط در محیط سرور می‌ماند. ثبت موفق درخواست، رسید تحویل گوشی نیست. خطای شبکه به ارسال مجدد خودکار منجر نمی‌شود.

کد تصادفی شش‌رقمی، یک‌بارمصرف و معتبر برای دو دقیقه است؛ فقط هش آن ذخیره می‌شود. حداکثر پنج تلاش و فاصلهٔ ارسال یک دقیقه است. سهمیه: پنج پیام روزانه برای هر شماره، صد پیام روزانه برای کل سایت و ده پیام در پانزده دقیقه برای آدرس اتصال سرور. درخواست ناموفق هم سهمیه مصرف می‌کند. پشت پراکسی، سهمیهٔ آدرس اتصال ممکن است مشترک باشد.

چالش‌ها و سهمیه‌ها در MySQL مشترک هستند. کد به هدف ورود، ثبت‌نام یا بازیابی رمز وابسته است. ثبت‌نام و بازیابی مجوز یک‌بارمصرف پنج‌دقیقه‌ای می‌گیرند؛ فقط هش مجوز ذخیره می‌شود. تغییر رمز و مصرف مجوز و حذف تمام نشست‌های قبلی در یک تراکنش انجام می‌شود. ثبت‌نام حساب موجود را بازنویسی نمی‌کند. رمز با scrypt و salt تصادفی ذخیره می‌شود. ورود اجتماعی هنوز فعال نیست.

پیش از ارسال کد ورود یا بازیابی، وجود حساب بررسی می‌شود؛ برای شمارهٔ ثبت‌نام‌نشده پیامکی ارسال نمی‌شود. این بررسی محدودیت تلاش دارد. ثبت‌نام همچنان برای شمارهٔ تازه کد ارسال می‌کند.

مسیرهای POST با کنترل مبدأ و JSON: `/api/auth/otp/request`، `/api/auth/otp/verify`، `/api/auth/register` و `/api/auth/password/reset`. شماره یا شناسهٔ چالش به‌تنهایی مجوز ورود نیست.

راهنمای «کد تأیید نرسید؟» بررسی شماره، پوشهٔ مسدودی، انتظار برای ارسال دوباره و پشتیبانی اپراتور را توضیح می‌دهد.

`npm run check:sms` و `npm run check:auth-ui` از پیامک ساختگی استفاده می‌کنند. `npm run check:database` منطق واقعی MySQL، بازیابی رمز و ابطال نشست‌ها را در دیتابیس موقت مستقل بررسی می‌کند. دریافت واقعی پیامک باید با درخواست کد در سایت بررسی شود.
